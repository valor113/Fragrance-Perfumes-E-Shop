School PHP Project Defense

Maison Doree Fragrance E-Shop

This page explains the project in simple language so the author can prepare for the oral presentation.

1. Project Overview

The website is a luxury fragrance e-shop. It started as mostly static HTML, CSS, and JavaScript. It was converted into a pure PHP 8 project with MySQL/MariaDB database support.

The main dynamic entity is products. Products are shown on the shop page and managed in the administration area.

Technologies used: PHP 8, MySQL or MariaDB, PDO, sessions, HTML, CSS, and JavaScript.

2. Project Structure

  • app/Core contains the autoloader, database connection, authentication helper, and base controller.
  • app/Controllers contains classes that handle user actions like login, product save, product delete, and appointment form submit.
  • app/Models contains classes that communicate with database tables.
  • app/Views/admin contains reusable admin page parts.
  • admin contains the protected admin pages.
  • config/database.php stores database connection settings.
  • database/maison_doree.sql creates all tables and sample data.
  • partials stores the shared header, footer, and mobile menu.

3. OOP Explanation

The project uses classes, namespaces, constructors, and objects. This counts as OOP because logic is grouped into objects with clear responsibilities.

  • Database creates and returns the PDO connection.
  • Auth manages login sessions and admin protection.
  • Product works with the products table.
  • User finds admin users by email.
  • ProductController validates product forms and calls the Product model.
  • AuthController handles login and logout.
  • AppointmentController validates and saves appointment requests.

4. Database Explanation

The SQL file is located at database/maison_doree.sql. It creates the database maison_doree_shop.

  • products stores shop products, prices, images, stock, and active status.
  • categories stores collection cards.
  • product_categories connects products with categories.
  • admin_users stores admin login data and password hashes.
  • appointment_requests stores contact form submissions.
  • hero_slides stores home page hero images.
  • testimonials stores contact page testimonials.

5. CRUD Explanation

CRUD means create, read, update, and delete. In this project it is implemented for products.

  • Create: admin/create.php sends form data to ProductController, then Product::create saves it.
  • Read: admin/index.php lists all products, and shop.php lists active products for visitors.
  • Update: admin/edit.php loads one product and Product::update saves changes.
  • Delete: admin/delete.php calls Product::delete.

Data flow: form input goes to an admin PHP page, then to a controller, then to a model, then to the database through a prepared PDO statement. When data is displayed, it is escaped with htmlspecialchars.

6. Authentication Explanation

The admin area is protected by PHP sessions. Login is handled in admin/login.php and AuthController.

The database stores a hashed password, not the plain password. During login, password_verify compares the submitted password with the stored hash. If login succeeds, the user data is saved in $_SESSION.

Protected pages call Auth::requireAdmin. Logout is handled in admin/logout.php and clears the session.

7. Security Explanation

  • PDO is used instead of old mysql functions.
  • Prepared statements help prevent SQL injection.
  • password_hash and password_verify protect admin passwords.
  • Sessions protect the admin area after login.
  • Basic validation checks required fields and email format.
  • htmlspecialchars is used through the e() helper before outputting database data.

8. Dynamic Content

The shop products are loaded from the products table. Collections come from categories. The home hero slides come from hero_slides. Testimonials come from testimonials. The contact form saves to appointment_requests.

9. Presentation Preparation

What to say: "I converted a static fragrance website into a pure PHP project. I used OOP classes, PDO, prepared statements, MySQL tables, admin login, and CRUD for products."

Question: Why did you use PDO? Answer: PDO is a modern PHP database API and works with prepared statements, which improves security.

Question: Where is OOP used? Answer: In Database, Auth, model classes, and controller classes.

Question: How is the admin protected? Answer: Login creates a session, and admin pages check that session before allowing access.
